# TinyTube — Agent Instructions

Kid-safe YouTube viewer. A child can only watch videos from parent-approved channels; there is deliberately **no search, no suggestions, no external navigation, and no backend**.

This is a copy of [pathikrit/TinyTube](https://github.com/pathikrit/TinyTube) living in the `tinytube/` subdirectory of the Novel Downloader repository. Everything below describes this app only; the repository root's `CLAUDE.md` governs the rest. The one structural difference from upstream is deployment — see [Deploy](#deploy).

## Working style (owner's standing preferences)

- **Simplify aggressively.** The prime directive here: fewer files, fewer toolchains, less code. This repo went from Python-scraper + Makefile + 28 source files to one npm project with 8 flat source files — on purpose. Before adding a file, script, or dependency, ask whether an existing one can absorb the job. Prefer deleting over abstracting.
- **Never commit or push unless explicitly asked** ("commit", "push", `/shipit`).
- **Verify, don't assume.** Check claims empirically before acting on them: fetch the actual FA kit CSS to see which icons exist, run the downloader against the real API, run the suite after refactors. "Iterate till you make sure it works."
- Keep `README.md` tiny (badge + one setup line + run line); all detail lives here.
- Secrets via `.env` (gitignored) with a committed `.env.sample` naming the keys; anything needing a key must fail fast with copy-pasteable setup instructions, not a bare error.

## Architecture

Single top-level npm project (no Makefile, no Python): npm scripts are the only entry points, and the downloader is the webapp's own API client run under node.

```
channels.json ─▶ src/youtubeApi.js CLI (YouTube Data API, GH Actions cron) ─▶ public/videos.json ─▶ React SPA (GH Pages)
                                                                                                        │
                                                                                                 localStorage (watch history)
```

- `channels.json` — flat list: `[{channel, min_age?, max_age?}]`. `channel` may be a bare name (`JaredOwen` → `@JaredOwen`), `@handle`, `UC...` id, or full YouTube URL; ages default to 1/15. Prefer `UC...` ids: handles can be squatted by lookalike channels (the `@PeekabooKidz` handle belongs to a 1.6K-sub impostor of the 7.7M-sub real channel). When adding a channel, sanity-check the resolved subscriber count. The same flat `{channel, min_age, max_age}` shape is used in videos.json and in the settings localStorage model.
- `src/youtubeApi.js` — one file that is BOTH the webapp's Data API client (imported by settings/lib) AND the downloader CLI (`node src/youtubeApi.js`, guarded by an argv check; node builtins are lazily imported so vite never bundles them). Needs `YOUTUBE_API_KEY` (local: `.env`, loaded via `node --env-file-if-exists`; CI: repo secret). ~3 quota units per channel per run. `--seed` (the currently-deployed videos.json) is a per-channel stale fallback so one broken channel or API hiccup never blanks the site. Output `videos.json` (schema v2): `{schema_version, generated_at, channels: [{channel_id, channel_title, thumbnail, source_url, subscribers, video_count, view_count, made_for_kids, topics, min_age, max_age, videos: [{id,title,duration,thumbnail}]}]}`. Never commit `videos.json` or `.env` — both are gitignored.
- SPA — Vite + React 19 + Bootstrap 5 (CSS only) + react-youtube. Mobile-first (iPad/iPhone Safari), dark theme, installable PWA (manifest + apple meta tags). Deliberately flat `src/`: one file per feature — `main.jsx` (App shell + boot), `landing.jsx` (enroll + math gates), `gallery.jsx`, `player.jsx`, `settings.jsx`, `lib.js` (all non-UI logic + hooks), `youtubeApi.js`, `styles.css` — plus `tests/*.test.js*`. Keep it that way; do not re-split into per-component files.
- Icons — owner's Font Awesome Pro token, loaded in `index.html` via the direct release URL (`ka-p.fontawesome.com/releases/v7.3.0/css/pro.min.css?token=a22be8527e`) rather than the kit CSS, which is pinned to 6.7.2 and lacks FA 7 icons like `fa-remote`. Before using an icon, confirm it exists in that CSS. House style is `fa-sharp-duotone fa-regular` for UI glyphs, `fa-duotone` for the tv-retro brand mark. The token serves ONLY the Pro/Brands/Duotone/Sharp/Sharp-Duotone fonts — new FA 7 families (`fa-utility-duo`, `fa-jelly-duo`) and the `fa-semibold` weight have no font files, so duo styles render their two layers as two side-by-side glyphs (verified empirically with the quota stopwatch).
- `public/` — every file is load-bearing for the install-as-app experience: `manifest.webmanifest` (`display: standalone`; deliberately NO `orientation` key — see player bullet), `icons/*.png` (Android install/splash + iOS apple-touch-icon; the FA kit cannot replace these — OS installers need real PNGs), and generated `videos.json`.

## npm scripts (the only entry points)

- `npm run download` — fetch channels via YouTube Data API → `public/videos.json`; fails fast with setup instructions if `YOUTUBE_API_KEY` is missing
- `npm run dev` — `predev` downloads videos.json if missing, then watch mode: vite dev server (`http://localhost:5173`; the `/novels/tinytube/` base path applies only to production builds) and vitest re-running affected tests on change, side by side via `concurrently`
- `npm test` — vitest suite (`tests/*.test.js*`: gallery sort logic + VideoPlayer lifecycle with a mocked react-youtube)
- `npm run prod` — download + test + `vite build` (CI runs the same steps individually; see Deploy below)

## Key behaviors (do not regress)

- **Parent gate**: on a biometric-capable device, first load blocks on `EnrollGate` (`src/landing.jsx`) — nothing (not even the gallery) shows until a grown-up registers the device biometric (`src/lib.js` — serverless WebAuthn platform authenticator; Face ID/Touch ID/fingerprint via `userVerification: 'required'`, credential id in settings.passkeyId; a button because WebAuthn needs a user gesture). From then on the Parents button (gear, top right of gallery) triggers the OS biometric prompt directly; cancel/failed scan just returns to the gallery (no lockout mechanism). Devices WITHOUT a platform authenticator skip enrollment and protect parent mode with the `MathGate` (`src/landing.jsx`) 2-digit-addition gate (4 choices, 5-second countdown; wrong/timeout closes the gate). WebAuthn needs a secure context: localhost dev and the deployed HTTPS site work, LAN-IP dev URLs don't (those fall back to the math gate).
- **Settings** (parent-gated; `src/settings.jsx`): draft-edit model — changes accumulate in memory and only a Save button (appears when dirty) persists; back/edge-swipe discards. Age dual-slider (values on the thumbs); API-key row inside a real `<form>` with `autoComplete="current-password"` + hidden username so browser password managers offer to save the key; debounced (500ms, ≥3 chars — search.list costs 100 quota units; the follow-up channels.list enrichment is 1 unit and extra `part`s are free) autocomplete channel search whose result rows show the same stats/topics cells as the table; and a TanStack-Table channel editor (avatar+link | stats | topics | ages | delete). The ages cell holds the SAME `DualAgeSlider` as the global filter; its column reserves 55% width with a 420px minimum because a cramped 1–15 dual slider is unreadable (narrow screens h-scroll via `table-responsive` — do not shrink the slider instead). Deleting curated = hidden flag, restorable. Rows sort descending by min then max age; the header shows an in-range counter (`Channel (8/10)`) and rows outside the global age filter gray out live. All via the **parent's own** Data API v3 key (stored locally; the deployed site ships no key — the CI `YOUTUBE_API_KEY` is build-time only). Custom-channel videos come from the long-form uploads playlist (`UULF` + channel id suffix, excludes Shorts, 18+ `ytAgeRestricted` filtered out) via `src/youtubeApi.js`, cached 24h. The header's top-right links the built commit (`__COMMIT_SHA__` via Vite define, from `git rev-parse HEAD`).
- **Age filter**: settings-driven — a channel shows when its `[min_age, max_age]` (curated value, or the parent's per-channel override) overlaps the global range (inclusive); see `src/lib.js`.
- **Kid-proof player** (`src/player.jsx`): www.youtube.com embed (NOT youtube-nocookie — it misfires as error 150 on mobile) with `controls:0, rel:0, fs:0, disablekb:1`; a transparent `TouchShield` swallows all touches; any non-playing state shows the opaque `PausedOverlay` so YouTube's "More videos" tray / end screen is never visible or tappable; ENDED → mark watched → back to gallery (no auto-advance).
- **Orientation**: gallery/settings always follow the device; ONLY the player forces landscape — `screen.orientation.lock` after fullscreen on Android, CSS 90° rotation fallback on iOS (`styles.css` portrait+coarse media query). Never put `orientation` in the manifest: installed PWAs honor it globally and lock every screen.
- **Watch quota** (`src/lib.js` quota section + `useWatchStore.usage`): parent-set cap (settings `quotaMins`, 0–240 in 15-min steps, default 180; 0 = no watching, there is deliberately no "off") on cumulative PLAYING seconds per **rolling 12h window** — the window starts at the first counted second and expires lazily on read (no timers). Only playing time counts: the player buffers seconds in a ref and flushes through the same save points as progress (every 5th playing tick, pause, hide, unmount). The player top bar shows "xx min remaining"; hitting zero mid-video hard-stops onto the `QuotaGate` screen (`src/landing.jsx`) — otherwise a video started with 1 min left would play out free. Gallery taps are checked at tap time (so lazy expiry unblocks immediately) and route to `QuotaGate`, whose Parents button reuses the same gate dispatch as the gallery's. Settings shows used-vs-quota as a fill on the quota slider (thumb label inside the thumb, h:mm) with a Session/24Hr/WTD/MTD/YTD stats table inline on the same row (hour buckets kept 48h for a true rolling 24Hr; day buckets kept 366 days; weeks start Sunday). There is deliberately no "reset usage" control: dragging the quota above what's used grants time, and the 12h expiry clears usage on its own.
- **Gallery sort** (`src/lib.js: gallerySort`): (1) in-progress 20–95% watched, closest-to-finish first; (2) unwatched, round-robin interleaved across channels so high-volume channels can't flood quiet ones; (3) abandoned <20%; (4) watched >95% last (the tail is usually credits).
- **localStorage** keys: `tinytube:v1` watch history `{lastVideoId, watched: {id: {pos, dur, completed, updatedAt}}, usage: {window: {start, secs}, days: {'YYYY-MM-DD': secs}, hours: {'<epochHour>': secs}}}` (watched LRU-capped 500, saved every 5 s while playing; usage feeds the quota + stats); `tinytube:settings:v1` parent settings `{apiKey, ageRange, quotaMins, customChannels: [{channel_id, channel_title, thumbnail, min_age, max_age}], overrides: {channel_id: {min_age?, max_age?, hidden?}}, passkeyId}` (mirrors the flat channels.json shape; legacy hiddenChannels/ageOverrides/parentLockUntil fields are dropped or folded into `overrides` on load); `tinytube:videocache:v1` custom-channel video cache `{[channel_id]: {fetchedAt, videos}}` (24h TTL).

## Testing notes

- `tests/App.test.jsx` and `tests/MathGate.test.jsx` partially mock `src/lib.js` (`vi.mock` with `importOriginal` spread) because the gate functions share a module with hooks that must stay real — keep that pattern when adding mocks.
- `src/main.jsx` guards its `createRoot` on `#root` existing so tests can import `App` under jsdom; don't remove the guard.

## Deploy

Upstream's `deploy.yml` is not part of this copy. A repository gets ONE GitHub Pages deployment, and this one already publishes the Novel Downloader landing page, so a second Pages workflow would not coexist — whichever ran last would replace the other's entire site. Both are staged into one artifact by the repository root's **`.github/workflows/pages.yml`**: push to `main` + weekly cron (Sun 06:00 UTC) + after every android build + manual → npm ci / download (with `--seed` from the live site) / test / build → `site/tinytube/` → Pages, live at `https://vtlinh.github.io/novels/tinytube/`.

Vite `base` comes from `BASE_PATH` (defaults to `/novels/tinytube/`, build only); `pages.yml` derives it from `$GITHUB_REPOSITORY` and passes it explicitly.

`.github/workflows/tinytube.yml` runs `npm test` and a keyless build on every pull request touching `tinytube/**` — a break caught there is a break that never stops `pages` and takes the landing page and APK download down with it.

`YOUTUBE_API_KEY` is an optional Actions secret. With it, the weekly run rebuilds `videos.json` from `channels.json`; without it, `pages.yml` republishes the deployed `videos.json` (or an empty channel list on a first run) so the app still loads and a parent can add channels with their own key. GitHub repo setting required once: Settings → Pages → Source = "GitHub Actions" (`pages.yml` passes `enablement: true`, which flips this on the first run).
